## What we did

1. **Reproduced the paper.** We coded the standard game and the Bayesian game and checked that we get the same tables (III, V, VII) and the same equilibria as the paper.
2. **Analysed it.** We looked at equilibrium selection (Pareto and risk dominance), the role of the constant P, and what the Bayesian equilibria really mean.
3. **Repeated play.** We simulated fictitious play to see which equilibrium the robots end up at if they play many times.
4. **Our extension.** In the paper, payoffs never depend on whether the item is actually defective. We built a defect-aware version: the scan accuracy depends on scan mode and item complexity, and the arm sees the scan result before moving. We solved it with backward induction.

## Setup (implementation environment)

We used Python 3.10+ on Ubuntu / Windows. Only numpy, matplotlib and pytest are needed.

```bash
git clone https://github.com/backpropy-hit/Game_Theory_Project.git
cd gt-project
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## How to run

```bash
python paper_game.py      # prints the paper's tables and equilibria
python learning.py        # fictitious play result
python defect_game.py     # extension results for a few defect rates
python make_figures.py    # all figures + CSVs
python -m pytest -q       # 13 tests
```

## Dataset resources

There is no external dataset. This is a theoretical project, so all data is generated by our code.

- `results/bayesian_equilibria_pq.csv`: Bayesian Nash equilibria for a 50x50 grid of error probabilities (p, q).
- `results/extension_results.csv`: our extension's equilibrium and losses for different defect probabilities.

The payoff values come from Table I of the paper. The detection rates, breakage rates and losses in `defect_game.py` are **our own assumptions** chosen to be reasonable; they are not measured data.
